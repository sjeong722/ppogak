# 문의 자동 기록 워크플로

여러 채널로 들어오는 문의를 공통 기준으로 정리해 Google 스프레드시트에 기록하는 자동화의 현재 설계와 시험 결과를 정리합니다. 첫 범위는 문의 접수·기록이며, 회의 후속 업무와 답변 작성은 포함하지 않습니다.

## 현재 상태

- 가상 인입 데이터로 문의 분류 규칙과 예외 처리를 검토했습니다.
- 별도 가상데이터 파일럿 시트에서 모의 전사 7건과 기존 시트 열로의 행 매핑 5건을 구성했습니다.
- Zoom 통화 자동 녹음·전사, 채널별 이벤트 수집, 실제 업무 시트 기록은 아직 연결하거나 검증하지 않았습니다.
- 실제 문의 데이터와 개인정보는 이 저장소에 포함하지 않습니다. 가상 인입 원본 파일은 배포 대상에서 제외합니다.

## 합의된 처리 기준

- 우선 채널은 전화입니다. 전화 접수량은 하루 약 10~50건이며 중복을 제외하면 약 10~30건입니다. 다음 채널은 공용 팀메일, 카카오톡, 홈페이지 순입니다.
- 전화는 Zoom Phone 070, 삼성 Android 법인 휴대전화 010, 대표번호가 연결되는 사무실 유선전화 순으로 조사합니다.
- 첫 메일 수집 범위는 다우오피스 공용 팀메일입니다. 담당자 개인 메일은 제외합니다.
- 전화는 문자 원문(녹취 전사 또는 상담 메모)을 확보한 경우에만 자동 기록 대상으로 삼습니다.
- 문의 유형은 `구매견적`, `계정문의`, `사용법`, `기타`입니다. 유형을 판단할 근거가 부족하면 `확인 필요`로 둡니다. 이용 인원 변경은 `계정문의`입니다.
- 새 문의는 기존 문의를 수정·병합하지 않고 별도 행으로 추가합니다. 같은 학교·상품이어도 교사 문의와 행정실 문의는 별도 건입니다.
- 같은 원본 이벤트의 재처리만 `source_event_id`로 막습니다. 담당자 배정 근거가 없으면 `확인 필요`, 초기 진행 상태는 `대기중`으로 기록합니다.

## 다음 작업

화요일 출근 후 Zoom Phone 070의 녹음·전사 기능과 라이선스·관리자/API 권한, 삼성 010 기본 전화 앱의 녹음 기능, 사무실 전화의 통신사·전화 시스템을 확인합니다. 녹음 설정 변경 전에는 사내 고지와 보관 기준도 확인합니다. 그다음 가상 데이터 시험을 보완하고 실제 연결 가능 여부를 판단합니다.
